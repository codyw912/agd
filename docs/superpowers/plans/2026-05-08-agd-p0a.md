# AGD P0a Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the narrow local workflow where `agd init` creates an isolated agent clone, unsigned agent commits avoid the human signer, explicit signing is denied, pushes are disabled, and `agd bless` adopts an agent branch as one human-signed squash commit.

**Architecture:** Start as one Rust binary crate with small modules around CLI parsing, path resolution, Git subprocess execution, project metadata, workspace setup, guardrails, and adoption. System Git is the source of truth; AGD writes only metadata, local Git config, marker files, hooks, and refs needed for the workflow.

**Tech Stack:** Rust, `clap`, `serde`, `serde_json`, `toml`, `anyhow`, `thiserror`, `camino`, `dirs`, `uuid`, `time`, `sha2`, system `git`, shell integration tests.

---

## File Structure

- `Cargo.toml`: crate metadata, binary target, dependencies, dev dependencies.
- `src/main.rs`: process entry point and top-level error reporting.
- `src/cli.rs`: `clap` command definitions for `init`, `path`, `status`, `bless`, and hidden `deny-signer`.
- `src/git.rs`: thin wrapper for `git -C <dir> ...` commands with structured stdout/stderr errors.
- `src/paths.rs`: AGD home, project metadata, workspace, marker, log, and helper paths.
- `src/project.rs`: project metadata types, load/save, project discovery from human and workspace markers.
- `src/workspace.rs`: managed clone creation, workspace marker creation, agent identity config.
- `src/guardrails.rs`: signing denial config, push denial config, pre-push hook, protected branch warning.
- `src/adoption.rs`: P0a squash bless flow, lock, safety ref, dirty checks, provenance trailers.
- `src/output.rs`: human-readable command output.
- `tests/p0a.rs`: integration tests using real temporary Git repositories and fake signer scripts.
- `scripts/manual-proof.sh`: manual end-to-end proof of the core workflow.
